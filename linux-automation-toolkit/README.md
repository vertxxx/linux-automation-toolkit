# Linux Automation Toolkit

Набор утилит на Python и Bash для автоматизации типовых задач системного администрирования и DevOps.

Проект включает анализ HTTP-логов, проверку доступности веб-сервисов и создание резервных копий каталогов.

## Возможности

### 1. Анализатор HTTP-логов

Python-скрипт для анализа журналов HTTP-запросов и формирования отчёта.

**Возможности:**
- Подсчёт общего количества строк и успешно обработанных запросов.
- Определение некорректных строк.
- Статистика по HTTP-кодам ответа и их классам.
- Определение пяти IP-адресов с наибольшим количеством запросов.
- Экспорт результатов в JSON.

**Пример запуска:**

```bash
python scripts/log_analyzer.py samples/access.log --json reports/log_report.json
```

Отчёт будет сохранён в `reports/log_report.json`.

### 2. Проверка доступности веб-сервисов

Python-скрипт для проверки доступности сервисов по HTTP и HTTPS.

**Возможности:**
- Проверка одного или нескольких URL.
- Измерение времени ответа.
- Вывод HTTP-кодов и ошибок соединения.
- Настройка тайм-аута запросов.
- Сохранение результатов в JSON.
- Возврат ненулевого кода завершения, если хотя бы одна проверка завершилась неудачно.

**Проверка одного сервиса:**

```bash
python scripts/health_check.py https://example.com
```

**Проверка нескольких сервисов с сохранением отчёта:**

```bash
python scripts/health_check.py \
  https://example.com \
  https://httpbin.org/status/200 \
  --timeout 5 \
  --json reports/health_report.json
```

### 3. Утилита резервного копирования

Bash-скрипт для создания сжатых архивов каталогов в формате `.tar.gz`.

**Возможности:**
- Проверка существования исходного каталога.
- Автоматическое создание каталога для резервных копий.
- Добавление даты и времени в имя архива.
- Запрет размещения резервной копии внутри исходного каталога.
- Обработка ошибок и удаление незавершённого архива при сбое.

**Пример запуска:**

```bash
bash scripts/backup.sh samples backups
```

Первый аргумент — исходный каталог, второй — каталог для резервных копий.

Пример результата:

```text
backups/samples_20261015_173627.tar.gz
```

Имя архива будет зависеть от даты и времени запуска.

## Структура проекта

```text
linux-automation-toolkit/
├── scripts/
│   ├── log_analyzer.py
│   ├── health_check.py
│   ├── backup.sh
│   └── __init__.py
├── tests/
│   ├── test_log_analyzer.py
│   ├── test_health_check.py
│   └── test_backup.sh
├── samples/
│   └── access.log
├── reports/          # Создаваемые отчёты
├── backups/          # Архивы резервных копий
├── requirements.txt
├── .gitignore
└── README.md
```

Каталоги `reports/` и `backups/` предназначены для генерируемых файлов и исключены из отслеживания Git.

## Требования

- Python 3.10 или новее.
- `pytest` для запуска тестов Python.
- Bash и утилита `tar`.
- Git.
- Linux или WSL2 с Ubuntu для запуска Bash-скрипта в Windows.

## Установка и настройка

Клонируйте репозиторий и перейдите в его каталог:

```bash
git clone <ссылка-на-репозиторий>
cd linux-automation-toolkit
```

Создайте виртуальное окружение Python:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

Создайте каталоги для отчётов и резервных копий:

```bash
mkdir -p reports backups
```

## Тестирование

**Запуск тестов Python:**

```bash
python -m pytest -v
```

Тесты проверяют анализ HTTP-логов, формирование JSON-отчётов, обработку ошибок и работу проверки доступности сервисов.

**Запуск тестов Bash:**

```bash
bash tests/test_backup.sh
```

Проверяются создание архива, обработка отсутствующего исходного каталога и запрет резервного копирования внутрь исходного каталога.

## Используемые технологии

- **Python** — обработка логов, HTTP-проверки и формирование JSON-отчётов.
- **Bash** — автоматизация резервного копирования.
- **Linux / WSL2** — выполнение системных скриптов.
- **HTTP / HTTPS** — проверка доступности сервисов.
- **JSON** — формат хранения отчётов.
- **pytest** — автоматизированное тестирование Python-кода.
- **Git** — контроль версий.
